# 首次配置与上传权交接

这里配置的是 [Kindle 设备端](https://github.com/WanhaoZhang/kindle-device-autosync)。Mac 助手仅处理扫码、对应关系、交接和诊断，不导入阅读日志或提交阅读时长。需要 USB 导入与人工上传的用户使用独立的 [网页版项目](https://github.com/WanhaoZhang/kindle-native-reading-sync)。

首次安装可使用 [快速安装](QUICKSTART.md)，探针通过后在同一次 USB 连接上完成本页的扫码和配置导出，再由 KUAL 合并执行安装和导入。以下为单步说明。

## 网页选择候选书

已安装的设备可在页面顶部的“给新书选择微信读书版本”完成预匹配。接上 Kindle 后选择候选文件，搜索微信读书，核对作者和版次，勾选确认后点“确认并保存对应”。可以连续处理多本，刷新页面仍会保留。

自己上传到微信读书的书也可以对应：先在微信读书完成导入，再将“搜索来源”选为“只看我上传的书”，按微信读书中的书名或作者搜索。结果会标明“我上传的书”“我的书架”或“书城”；全部来源优先显示个人上传书。上传版和书城版是独立的目标 ID，书名相同也不能混用。选择准确目标后仍需人工确认，不会自动上传正文或把两个版本的记录合并。书架读取失败会明确提示；结果超过 40 项时请使用更具体的关键词。

候选列表只读取 USB 文件名和 Calibre 元数据，不读取正文。设备已经解析的来源键与尚未读过的候选文件分别标记。选择同名不同格式文件时分别保存，避免把文件名当作已验证的原生来源键。候选确认保存在 Mac 的 `.weread/book-candidates.json`，现有 `mappings.json` 和设备授权保持保留。

在 **Preview 0.2.0+** 上，保存好全部候选后，勾选导出确认，点“导出候选对应到 Kindle”。安全弹出拔线，在 KUAL 选择 **Import selected books + export status**。多本候选一次导入即可。

设备把候选作为独立、追加的对应注册表保存到私有目录，保持原配置绑定、授权与账本。已存在的对应不能改指向另一本微信读书书籍。同名重复文件或不同格式造成来源键冲突时拒绝导入，应只选其中一份。

未读候选先等待。以后原生阅读、关书并形成完整计时窗口时，只有真实会话来源键、唯一 sidecar 计数和对应文件路径一致，才参与同步。其他来源身份继续等待，不根据书名猜测。新增候选后的普通联网、关书或自然唤醒事件触发同步；导入动作本身只写本地对应。

旧设备版本必须先升级才能使用此入口，页面会检查设备导出状态中的能力字段。修改旧版基础 `mappings.json` 的传统导入仍会使授权绑定失效，追加新候选请走页面顶部的新入口。

只读搜索可使用本机已有的独立 Mac 查询凭据 `.weread/catalog-auth.json`。未配置该文件时沿用 Kindle 专用凭据进行查询；该文件和所有候选清单都由 Git 忽略。它只用于书籍搜索，不用于时长写入。

## 1. 先验证设备

按 [设备安装说明](../device/install/README.md) 完成适配当前 PW2 固件的 root 环境、自检及只采集安装。先保持飞行模式，完成一次原生阅读、关书、合盖/唤醒、USB 接回测试。在 KUAL 选择 `Export sanitized status` 后接回 Mac，助手的诊断内容才是最新导出快照；页面不能实时查询已经拔线的 Kindle。

`private_filesystem_ok=true` 只代表候选 worker 的本地文件/SQLite 自检成功。服务启动、日志增长、睡眠、USB、联网 TLS、性能和入账分别核验，不由一个自检按钮统一判定。

## 2. 选择交接来源

先运行 `./setup.sh`。首次只查看连接与诊断时，可直接运行 `./启动设备配置.command`，访问 `http://127.0.0.1:8766/`。

### 曾经用网页版上传

使用明确的实际工作目录启动：

```sh
.venv-bridge/bin/python device_app.py --legacy-project "/absolute/path/to/existing-web-project" --open-browser
```

该目录应包含真正使用过的 `.weread/sync-engine.sqlite` 及原登录资料，而不是新克隆的公开源码目录。助手验证已有账本；不会因为选错空路径就新建一个“没有历史”的旧账本。

交接会与原上传实例使用同一个 SQLite 写锁，阻止正在发送或提交的实例被切走；之后写入原项目的封锁标记，使该网页版实例停止提交阅读时长。原始日志、凭据、映射、已确认量及待核验记录仍留在原处。已有待核验结果需明确选择保留，不能在设备上重试；任何旧待核验秒数都不计入新设备起始余额。

### 纯新用户

只有确实没有旧上传实例时，才选择新设备初始化并明确确认。若发现已有旧实例，应回到迁移流程。不要删除、移动或换一个空目录来绕过此检查。

两个仓库可独立运行；新用户不必安装网页版。使用过网页版的用户需要对实际旧实例完成一次交接，因为独立的空账本不能证明旧请求没有执行。

## 3. Kindle 专用扫码

在配置页生成二维码，用微信扫描并在手机上确认。登录会为 Kindle 生成独立设备身份，不复用 Mac 正在使用的 `deviceId`，也不覆盖旧 Mac 的登录文件。迁移时必须为同一微信读书账号；账号不匹配会拒绝导出。

扫码及书架核验会联网，但不会提交阅读时长。二维码为临时授权资料，不要分享截图；凭据只保存在本机私有目录。设备会在上传前按规则尝试令牌续期，但不能保证永久有效。续期失败后的重新授权属于身份维护，不能直接覆盖原凭据或新建账本，见后文。

## 4. 核对书籍映射

### 纯新用户先完成一次空映射导入

首次没有本地来源键时，不需要猜测。先保留映射为 `[]`，明确初始化并交接新设备，按下一节完成配置导出和 Kindle 导入。此时仍只采集、不会上报。

随后在原生阅读器打开一本书进行**交接后的新阅读**，关书等待空闲；在 KUAL 点 `Export sanitized status` 后接回。助手点“读取已解析书籍”，从 worker 的 `status.books` 列表取得准确的 `local_book_id` 和标题，再只读搜索微信读书并核对具体版本、作者和书籍 ID。没有成功解析到来源键时继续保留数据并诊断，不用标题代填。

已有网页版对应关系时，可点“载入旧书籍对应”，复用原来明确确认的版本；本地书籍、微信版本或账号变化后应重新核对。

### 保存并再次导入

设备配置中的每项对应关系包含：

```json
[
  {
    "local_book_id": "EXACT_KINDLE_SOURCE_KEY",
    "weread_book_id": "EXACT_WEREAD_BOOK_ID",
    "title": "核对过的具体版本"
  }
]
```

`local_book_id` 是解析器识别出的精确来源键，`weread_book_id` 是你确认的微信读书具体版本 ID。标题只是便于核对的显示文字，不参与模糊猜测。旧项目中已确认的映射可以带入；新书尚未核准时先保留采集，不随意填写另一部同名书。

编辑映射 JSON 后点“保存书籍对应”，核对结果，再导出、在 Kindle 导入更新配置。助手提供设备已解析 ID 和微信读书只读搜索，不包含 Mac 日志导入工作流。没有匹配的会话不会被自动记入其他书，映射变化也会令旧验收绑定失效。

本项目只同步时长，不上传电子书正文、购买书籍或自动新增书架。微信读书没有准确版本时，应先自行导入合法持有的电子书，再核对目标 ID。

## 5. 确认交接并导出

核对设备 root 探针、账号、对应关系和待核验记录后，再明确确认交接与 USB 导出。交接固定新采集窗口的起始时间，原 Mac 的写入封锁不会因导出失败而自动解除。

USB 暂存目录是 `.kindle-native-sync-inbox/`，包含配置、专用认证文件和三个文件的校验交接材料。FAT 无法保证 `0600` 私有权限；请在自己的电脑和设备之间交接，并在安全弹出后及时从 KUAL 选择 `Import USB configuration`。

worker 核验 hash、账号、设备及原账本身份，然后将配置和凭据原子保存到 `/var/local/kindle-native-sync/`。导入成功只删除已验证的交接文件；若失败，不盲目覆盖暂存目录。原 Mac 保持封锁，先诊断；不再需要的失败暂存凭据应及时人工清理。

## 6. 继续只采集验收

导出、导入后的配置默认仍为：

```json
{"device_validation": false, "protocol_validation": false, "binding_sha256": ""}
```

助手不会替你把性能、休眠或入账门禁改为通过。变更书籍映射、升级二进制等操作可能使旧绑定失效，必须重新核对。

完成 [真机验收清单](DEVICE_VALIDATION.md) 后，才可整理真实验收证据，并按 [worker 说明](../device/worker/README.md) 对新增真实完整短会话准备不可变计划、核对后试传。HTTP 成功或 `succ=1` 不能单独确认到账；请求结果未知时不得重发。不能将已确认或旧待核验时长迁入空账本当作新阅读。

当前项目仍处于此验收流程中，尚不应宣传为安装后立即可稳定自动同步。

## 重新授权与身份维护

若本机已经存在 Kindle 专用凭据，配置助手会拒绝再次扫码覆盖。普通令牌续期由设备 worker 在写入前处理，并核对账号不变；这与重新扫码产生新 `deviceId` 是两件事。

已有设备账本绑定原身份、账号和起始窗口。重新扫码生成的另一身份不能直接覆盖这份账本；本版没有承诺无缝切换身份的恢复流程。续期失败时先保留 Mac/Kindle 凭据、账本和所有未决记录，停止新写入，核对具体失败原因后再做维护迁移。不要删除 `device-auth.json` 或账本来强制重新扫码，也不要把新生成的身份当作原来未知请求已经失败的证据。
